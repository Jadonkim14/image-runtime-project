# V0.3 — Pipeline Structure Analysis

## 1. 목표

V0.3의 목표는 기존 OpenVINO 이미지 분류 프로그램의 실행 경로를 단계별로 분리하고, 각 단계의 실행 시간을 측정하여 실제 비용 분포를 파악하는 것이다.

이 단계에서는 성능 최적화를 수행하지 않는다.

핵심 진행 순서는 다음과 같다.

```text
Execution Structure Analysis
        ↓
Stage-level Measurement
        ↓
Cost Distribution Analysis
        ↓
Profiling Target Selection
```

Thread Pool, Async Inference, Pipeline, Scheduler, GPU Scheduling 등의 구조 변경은 수행하지 않는다.

## 3. 실행 구조 분석

현재 `main.c`의 주요 실행 경로를 다음과 같이 분리하였다.

```text
Process Start
    ↓
OpenVINO Core Initialization
    ↓
Model Load
    ↓
Image Load
    ↓
Tensor Preparation
    ↓
Preprocessing Configuration
    ↓
Model Compile
    ↓
Infer Request Creation
    ↓
Input Tensor Set
    ↓
Synchronous Inference × 100
    ↓
Result Processing
    ↓
Process Exit
```

### Model Load

주요 API:

```c
ov_core_read_model()
```

ONNX model을 OpenVINO model representation으로 읽는다.

### Image Load

주요 함수:

```c
image_read()
```

입력 BMP 이미지를 메모리로 읽는다.

### Tensor Preparation

주요 API:

```c
ov_shape_create()
ov_tensor_create_from_host_ptr()
```

입력 이미지의 shape을 생성하고 이미지 메모리를 OpenVINO tensor와 연결한다.

이번 V0.3에서는 두 API를 하나의 `Tensor Preparation` 구간으로 측정하였다.

### Preprocessing Configuration

주요 API:

```c
ov_preprocess_prepostprocessor_create()
ov_preprocess_input_tensor_info_set_from()
ov_preprocess_input_tensor_info_set_layout()
ov_preprocess_preprocess_steps_resize()
ov_preprocess_input_model_info_set_layout()
ov_preprocess_prepostprocessor_build()
```

입력 tensor layout, resize 및 model layout 등 preprocessing 동작을 구성한다.

### Model Compile

주요 API:

```c
ov_core_compile_model()
```

model을 지정된 CPU device에서 실행할 수 있도록 compile한다.

### Infer Request Creation

주요 API:

```c
ov_compiled_model_create_infer_request()
```

compiled model로부터 infer request를 생성한다.

### Input Tensor Set

주요 API:

```c
ov_infer_request_set_input_tensor_by_index()
```

준비된 input tensor를 infer request에 설정한다.

### Synchronous Inference

주요 API:

```c
ov_infer_request_infer()
```

동일한 input tensor에 대해 synchronous inference를 100회 수행한다.

### Result Processing

주요 API 및 함수:

```c
ov_infer_request_get_output_tensor_by_index()
tensor_to_infer_result()
infer_result_sort()
```

output tensor를 가져와 classification result로 변환하고 정렬한다.

콘솔 출력 함수인:

```c
print_infer_result()
```

는 Result Processing 측정에서 제외하였다.

## 4. 측정 방법

각 stage의 wall-clock elapsed time을 측정하기 위해 다음 API를 사용하였다.

```c
clock_gettime(CLOCK_MONOTONIC, ...)
```

기본 측정 구조:

```c
clock_gettime(CLOCK_MONOTONIC, &start);

target_operation();

clock_gettime(CLOCK_MONOTONIC, &end);
```

elapsed time은 millisecond 단위로 계산하였다.

```c
(end.tv_sec - start.tv_sec) * 1000.0
+ (end.tv_nsec - start.tv_nsec) / 1000000.0
```

각 stage의 측정은 프로그램의 동작 구조를 변경하지 않고 timing instrumentation만 추가하는 방식으로 수행하였다.

## 6. Inference Latency

100회의 synchronous inference latency도 기존 방식과 동일하게 측정하였다.

| Metric | Run 1 | Run 2 | Run 3 | Mean |
|---|---:|---:|---:|---:|
| Average | 1.272 ms | 1.221 ms | 1.215 ms | **1.236 ms** |
| P95 | 1.373 ms | 1.377 ms | 1.521 ms | **1.424 ms** |
| P99 | 1.546 ms | 1.430 ms | 2.431 ms | **1.802 ms** |

Run 3에서 P99 latency가 `2.431 ms`까지 증가하였다.

그러나 각 실행당 sample 수가 100개뿐이므로 현재 P99 결과만으로 안정적인 tail-latency 특성을 판단하지 않는다.

## 7. Stage Cost 분석

측정된 one-time setup stage 중 가장 큰 비용은 `Model Compile`이었다.

3회 평균:

```text
Model Compile                 81.617 ms
Model Load                    22.943 ms
Preprocessing Configuration    4.313 ms
Image Load                     0.224 ms
Infer Request Creation         0.126 ms
Result Processing              0.128 ms
Input Tensor Set               0.027 ms
Tensor Preparation             0.014 ms
```

현재 측정에서는 다음과 같은 비용 규모 차이를 확인하였다.

```text
Model Compile
    ↓
Model Load
    ↓
Preprocessing Configuration
    ↓
Other Stages (< 1 ms)
```

특히 `Image Load`, `Tensor Preparation`, `Infer Request Creation`, `Input Tensor Set`, `Result Processing`은 각각 1 ms 미만이었다.

---

## 8. Model Compile 해석

`Model Compile`은 평균 약 `81.617 ms`로 측정되어 개별 stage 중 가장 큰 시간을 사용하였다.

그러나 이를 전체 workload의 최종 bottleneck으로 판단하지 않는다.

현재 benchmark 구조에서는:

```text
Model Load       ─┐
Image Load        │
Tensor Preparation│
Preprocessing     │
Model Compile     ├── One-time Cost
Request Creation  │
Input Tensor Set ─┘

        ↓

Inference × 100
```

과 같은 구조를 가진다.

Model Compile은 프로세스 실행 중 한 번 수행되지만 inference는 100회 반복된다.

평균 inference latency를 기준으로 단순 계산하면:

```text
1.236 ms × 100
≈ 123.6 ms
```

이다.

따라서 단일 호출의 latency만 비교하여 bottleneck을 결정할 수 없다.

각 stage의 실행 빈도와 전체 workload에서의 누적 비용을 함께 고려해야 한다.

## 9. V0.3에서 확인한 핵심 사항

### 9.1 Stage별 비용 차이

프로그램 내부의 각 stage가 동일한 비용을 가지지 않는다는 것을 실제 측정을 통해 확인하였다.

특히 one-time setup path에서는 `Model Compile`과 `Model Load`가 상대적으로 큰 비용을 사용하였다.

### 9.2 단일 호출 비용과 전체 비용은 다르다

`Model Compile`은 한 번의 실행 비용이 크지만 한 번만 수행된다.

반면 inference는 한 번의 latency가 약 `1.236 ms`이지만 100회 반복된다.

따라서 성능 분석에서는 다음 두 요소를 함께 고려해야 한다.

```text
Cost per Operation
×
Execution Frequency
```

### 9.3 작은 stage는 우선순위가 낮다

현재 측정에서 다음 stage들은 모두 1 ms 미만이었다.

```text
Image Load
Tensor Preparation
Infer Request Creation
Input Tensor Set
Result Processing
```

현재 단계에서는 이 함수들을 더 세분화하여 분석하는 것보다 전체 CPU 실행 위치를 profiling하는 것이 우선이다.

필요할 경우 이후 profiling 결과에 따라 특정 stage를 다시 세분화한다.

## 10. 측정의 한계

현재 V0.3 결과에는 다음과 같은 제한이 있다.

### 동일 이미지와 동일 tensor 반복

100회의 inference는 100개의 서로 다른 이미지를 처리한 것이 아니다.

동일한 `banana.bmp`에서 생성한 하나의 input tensor를 반복 사용한다.

따라서 현재 결과는 실제 multi-image pipeline 전체의 latency를 의미하지 않는다.

### One-time Cost와 Per-request Cost의 혼재

Model Load, Preprocessing Configuration, Model Compile 등은 한 번 수행되지만 inference는 100회 수행된다.

따라서 모든 stage의 millisecond 값을 단순 비교하여 bottleneck을 결정할 수 없다.

### 3회 반복 측정

Stage-level 결과는 동일 조건에서 3회 측정하였다.

이는 비용 규모를 파악하기 위한 초기 측정이며 정밀한 통계 분석을 위한 충분한 sample 수는 아니다.

### Inference P99

각 실행에서 inference sample 수가 100개이므로 P99 값은 극소수 sample의 영향을 크게 받을 수 있다.

따라서 현재 P99는 참고 값으로 사용하며 안정적인 tail-latency 지표로 해석하지 않는다.

### Instrumentation Overhead

각 stage 전후에 `clock_gettime()`을 호출하므로 작은 측정 overhead가 존재한다.

특히 수십 microsecond 수준의 매우 짧은 stage에서는 상대적인 영향이 커질 수 있다.

## 12. V0.3 결론

V0.3에서는 기존 OpenVINO 이미지 분류 프로그램의 실행 경로를 stage 단위로 분리하고 각 stage의 elapsed time을 직접 측정하였다.

One-time setup path에서는 `Model Compile`이 평균 약 `81.617 ms`로 가장 큰 개별 비용을 보였고, `Model Load`는 평균 약 `22.943 ms`, `Preprocessing Configuration`은 평균 약 `4.313 ms`였다.

반면 Image Load, Tensor Preparation, Infer Request Creation, Input Tensor Set 및 Result Processing은 현재 workload에서 각각 1 ms 미만으로 측정되었다.

Synchronous inference는 평균 약 `1.236 ms`였으며 현재 workload에서는 동일한 input tensor에 대해 100회 반복된다.

따라서 단일 stage의 latency만으로 bottleneck을 결정하지 않고, 각 stage의 실행 빈도와 전체 workload에서 차지하는 누적 비용을 함께 고려해야 한다.

V0.3에서는 최적화 대상을 확정하지 않는다.

다음 단계에서는 Linux profiling 도구를 사용하여 CPU 실행 시간이 실제로 어떤 함수와 library 내부에 집중되는지 분석한다.

```text

        ↓
V0.3 Pipeline Structure Analysis
        ↓
V0.4 Profiling
        ↓
Bottleneck Identification
        ↓
Optimization Decision
```
